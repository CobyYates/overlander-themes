How each option fits this app

The site's photo traffic has a clear shape. Browse pages and feeds load one small thumbnail per item, so thumbnails make up most of the loads. Full galleries only load when someone opens a listing, post or group. Older content builds up and is rarely opened. The cheapest option is the one that charges least for photos nobody is looking at.

Cloudflare Images

Bills for

Every photo stored ($5 per 100k) and every photo load ($1 per 100k).

Good
  • Already built into the app: uploads, deletes, sizes, signed message photos.
  • Any size on the fly through flexible variants.
Watch
  • The load charge grows with every page view.
  • Unseen old photos still count toward storage.

R2 + on-the-fly resizing

Bills for

Each distinct photo and size resized in a month ($0.50 per 1,000, first 5,000 free). Storage at $0.015 per GB.

Good
  • Unseen photos cost almost nothing.
  • Any size on the fly.
Watch
  • Cost climbs as more of the catalog gets browsed.
  • Needs a custom domain and new upload code.

Bunny.net storage + optimizer

Bills for

Storage ($0.01 per GB), bandwidth (about $0.01 per GB in North America) and a flat $9.50 a month for resizing.

Good
  • Predictable, and any size on the fly.
Watch
  • Another vendor and account to run.
  • Bandwidth grows with traffic.

Backblaze B2 + Cloudflare, sizes at upload

Bills for

Storage ($6.95 per TB) and a small charge per read past a daily free amount. Serving through Cloudflare is free.

Good
  • The cheapest storage once the site holds terabytes.
  • Same S3-style API as R2, so moving later is straightforward.
Watch
  • Two vendors and two bills.
  • At this app's current size the saving over R2 is cents.

R2, sizes made at upload

Bills for

Storage only ($0.015 per GB after 10 GB free). Serving is free, and reads stay under the 10M free each month at most sizes.

Good
  • The cheapest by far, and flat as traffic grows.
  • The app already uses R2 for file attachments, and private photos can use the same access-checked route.
  • The browser already converts uploads to WebP.
Watch
  • More build work than staying on Cloudflare Images.
  • A new size later means a script to make it for every existing photo.

If video gets added

Use a video service

Never serve raw uploads from storage. A video service converts each upload so it plays smoothly on any connection.

  • Cloudflare Stream: $5 per 1,000 minutes stored, $1 per 1,000 minutes watched. Simplest next to R2.
  • Bunny Stream: about $0.01 per GB stored and $0.005 to $0.01 per GB watched. Cheaper at volume, one more vendor.
Set limits

Cap file size and video length from day one.

How the numbers are worked out

  • Photo loads = browse views × thumbnails + detail views × gallery photos.
  • New photos are added each month from active users × photos per user, so storage keeps growing.
  • Resizing assumes 2 sizes per photo seen. Sizes made at upload add 35% to stored size (a 400px and a 1200px copy beside the full size).
  • Bunny transfer uses the average size per photo load. R2 and B2 assume 10% of loads miss the CDN cache and read from storage.
  • The two terabyte presets match an outside estimate (1 TB stored and 5 TB served a month at launch, 10 TB and 50 TB later). That's about 30 times this app's 10k-user scenario.
  • Not counted: the one-time work to switch, Cloudflare Pages and Supabase, and moving photos from the old Cloudflare account.
  • Prices are list prices as of late 2026 from what we know of each vendor. Check each vendor's pricing page before deciding.

Also looked at, and ruled out

  • Amazon S3 alone: serving costs $0.09 per GB, about $470 a month at 5 TB served.
  • S3 + CloudFront's $15 Pro plan: cheap at a glance, but storage is $0.023 per GB and the plan likely caps monthly requests far below what a photo site makes.
  • Wasabi: $7.99 per TB, but it isn't meant for sites that serve far more than they store, and it bills each file for at least 90 days.

Worth doing whichever option wins

  • Keep compressing photos to WebP in the browser before upload. The app already does this.
  • Send uploads straight to storage with a signed upload link, instead of passing the photo through the server first as it does today.
  • Set file-size limits on uploads.
